# Питомец Финни

Игровой сервис финансовой грамотности для детей **7–11 лет**. Прототип по ТЗ
Департамента финансов города Москвы.

Ребёнок заботится о питомце и учится делить монеты на **нужное**, **желаемое**
и **копилку**. Настоящих денег, рекламы, аккаунтов и сервера нет. Весь прогресс
лежит только на устройстве.

## Идея и правила продукта

Игра не про «накорми питомца кликами». Питомец растёт от **серии решений за
неделю**: закрыл нужное, отложил в копилку, факт похож на план. Одна покупка
шкалы чуть двигает, стадию не меняет.

Жёсткие ограничения из ТЗ, которые уже в коде:

- нет реальных платежей, рекламы, регистрации, облака;
- имя игрока — игровое, без почты и телефона;
- в минус уйти нельзя;
- без подтверждённого плана покупки закрыты;
- мини-игры за неделю дают не больше **80** монет;
- валюта в UI — **₽**, внутри это целые монеты;
- демо-недели включены по умолчанию (кнопка «Неделя», без ожидания календарных дней);
- раздел «Взрослым» закрыт примером `8 + 5 = 13`.

Старт: **100** монет, цель по умолчанию «Уютный домик». Доход за закрытую
неделю: **80**. Копилка при закрытии недели **не обнуляется**.

## Как идёт игра

```
иконка → заставка ~8 с
      → приветствие («Играть!»)
      → выбор Финни или Нори, цвета и своего имени
      → выбор локации
      → дом
```

Если профиль уже есть: заставка → сразу дом (локация уже записана).
Если видели приветствие, но питомца ещё нет: заставка → выбор персонажа.
Если питомец есть, а локация нет: заставка → выбор локации.

На доме после **первого** создания один раз идут 6 подсказок по значкам
(флаг `seenHomeHints`). Старые сохранения с питомцем считаются уже видевшими
подсказки, чтобы не показывать тур игрокам с прогрессом.

Типичная неделя:

1. **План** — разложить текущие монеты на нужное / желаемое / копилку и подтвердить.
2. **Активная фаза** — магазин, копилка, задания, мини-игры.
3. **Закрытие недели** (демо-кнопка) — сверка факта с планом, +80 монет, новый план.

Питомец на доме отвечает тапом облачком (~7 с) и разовой реакцией. После
задания, покупки, копилки и мини-игры клип ставится в очередь и играет, когда
дом снова на экране.

## Возможности

### Заставка

Нативная Android-заставка, затем арт: телефон — `fon_zagruzki_fast.jpg`,
планшет (shortest side ≥ 600) — `fon_zagruzki_planshet_fast.jpg`. Полоса
прогресса без названия над ней. Пока полоса идёт, в фоне поднимаются профиль,
музыка, HTTP-сервер клипов и один WebView. Держим экран **8 секунд**
(`AppSplash.hold`), даже если загрузка быстрее.

### Приветствие

Текст «Привет! Это игра…», краткая инструкция, зелёная **Играть!**.
На планшете кнопка прибита внизу экрана, не уезжает под складку.

### Персонаж

Два тела, у каждого свой набор из 15 GLB. На экране создания заголовок
«Выбери персонажа и цвет». Превью одно, на одном WebView. Оба idle грузятся
сразу и держатся на двух слоях: тап Финни ↔ Нори переключает слой, последний
тап побеждает.

| Кнопка | Тело | Модель |
|---|---|---|
| Финни | `PetBody.finni` | кот |
| Нори | `PetBody.nori` | лиса |

Цвет шерсти выбирается здесь же, до кнопки «Играть!»:

| Цвет | В профиле |
|---|---|
| Как есть | `PetColor.natural` — исходный окрас модели |
| Персик | `peach` |
| Мята | `mint` |
| Небо | `sky` |
| Волна | `wave` |
| Сирень | `lilac` |

Перекрас берёт альбедо из GLB и красит пиксели шерсти. Глаза и нос не
закрашиваются. «Как есть» возвращает исходную текстуру. На модели смена
цвета заметна, но не сплошным фильтром сверху.

2 тела × 5 окрасов = **10** видов — пункт ТЗ 2.6 (не меньше 9). «Как есть»
не считается отдельным окрасом, это отказ от перекраса.

Под моделью, пока имя пустое, одна строка: **«Здесь будет твой друг»**.
Финни и Нори там не пишутся — это только кнопки типа модели. Когда имя
введено — **имя и этап** (Малыш / Растёт / Настоящий друг). То же на доме.

Имя игрока и имя питомца — любые игровые, без почты и телефона. Кличка
в поле не подставляется сама. **Играть!** серая, пока не выбраны тело,
цвет (или «как есть») и имя питомца. На планшете кнопка прибита вниз.

На доме первое облачко: «Привет! Я {имя}!» — то имя, что придумал игрок.

Новый персонаж (меню «Новый питомец») **сбрасывает** монеты, задания, копилку
и локацию. Смена только комнаты прогресс не трогает.

### Локации и время суток

| Место | Когда |
|---|---|
| Теремок на лужайке | сразу |
| Усадьба у сада | после **5** выполненных заданий |

Фон комнаты зависит от часов устройства:

| Период | Часы |
|---|---|
| Утро | 6:00–16:59 |
| Вечер | 17:00–21:59 |
| Ночь | 22:00–5:59 |

У телефона и планшета свои JPEG (`bg_room_*` и `room2_*`, суффикс `_planshet`).
В APK попадают только файлы из `pubspec.yaml`. Сырые PNG комнат в сборку не входят.

### Дом

Комната, 3D-питомец на полу, HUD вокруг, облачко реплик.

- Слева сверху: монеты в кармане, копилка, динамик (музыка).
- Справа сверху: меню, «Взрослым», словарь.
- Слева у питомца: план, задания.
- Справа у питомца: магазин, копилка.
- Снизу на кремовой полосе: игры, прогресс, настроение, сытость, кольцо цели.
  Иконки выровнены по одному уровню (боксы 48 px).

Баннер текущего задания сверху: название, счётчик и полоска. Полоска обведена
серой рамкой, чтобы её было видно на светлом фоне.

Подсказки дома: затемнение, вырез и белая светящаяся рамка. На персонаже
рамка — прямоугольник по фигуре, не по всему квадрату WebView и не круглая точка.

Нижний ряд не перекрывается вырезом подсказки.

### План на неделю

Три доли: нужное, желаемое, копилка. Сумма не больше баланса. После
подтверждения фаза `planning` → `active`. Повторно подтвердить ту же неделю
нельзя. В плане нет жёсткого минимума на нужное (минимум 15 проверяется при
**закрытии** недели, не при сохранении плана).

### Магазин (24 позиции)

Без плана и в минус купить нельзя. Покупка сразу меняет сытость/настроение.

**Нужное:** корм, вода, расчёска, мыло, подушка, витамины, лекарство,
наполнитель, тёплая накидка, зубная щётка, миска, поводок.

**Желаемое:** мячик, тортик, бантик, воздушный змей, книжка, мыльные пузыри,
краски, пазл, мороженое, барабан, наклейки, фонарик.

### Копилка и цели (6)

Положить / снять. Снятие удлиняет срок до цели. Оценка срока — по среднему
отложенному за прошлые недели (`Economy.goalEta`).

| Цель | Стоимость |
|---|---|
| Уютный домик | 180 |
| Костюм героя | 260 |
| Палатка во дворе | 300 |
| Запас лакомств | 340 |
| Самокат | 420 |
| Велосипед | 500 |

Монеты мини-игр в копилку как «доход цели» не пишутся: они идут в карман.

### Задания (17)

Три темы: план, копилка, покупки. Два типа: выбор варианта и раскладка суммы.
Верный ответ — полная награда, иной — примерно половина (не меньше 5).
Задание один раз. После экрана — похвала и сколько монет пришло
(и за успех, и за попытку). Пятое выполненное открывает усадьбу.

1. Разложи 30 монет
2. Доход меньше желаний
3. Копилка на домик
4. Спрячь часть в копилку
5. Два ценника
6. Внезапная поездка
7. Друг зовёт в кино
8. Реклама «успей купить»
9. Подарок на день рождения
10. Обед или игра в телефоне
11. Нашёл 25 монет
12. Три цены на воду
13. Сломалась расчёска
14. Почти накопил
15. День на рынке
16. «Каждую неделю само»
17. Старая игрушка или новая

### Мини-игры (5)

Потолок **80** монет за неделю. Дальше играть можно, монет больше не дают
(в сообщении — что максимум на неделе выбран). «Копилка ловит» и «Лови монетки»
рисуют падение одной кистью (`Ticker` + `CustomPaint`), на экране не больше
8 и 10 объектов.

| Игра | Суть |
|---|---|
| Надо или хочу? | карточка в нужную сторону |
| Лови монетки | тап по падающим монетам, не хватать лишние траты |
| Три баночки | разложить по банкам |
| Копилка ловит | ловить копилку то, что стоит копить |
| Найди пары | пары карт |

### Прогресс и рост

Одно кольцо до выбранной цели, история недель (план / факт / заметка).
Очки роста за неделю:

- +1, если на нужное потрачено ≥ 15;
- +1, если в копилку что-то ушло;
- +1, если факт близок к плану (разница ≤ 10 или ≤ 35% доли).

Стадии: 0–2 очка — малыш, 3–5 — растёт, 6+ — настоящий друг.
Питомец на экране чуть масштабируется (0.92 / 1.0 / 1.12).

Если нужного не хватило, при закрытии недели сытость и настроение падают.
Если копил и попал в план — растут.

### Сытость и настроение

Не «голодный к утру». Убывание от штампа `needsAt`:

- сытость −1 раз в **5 часов**;
- настроение −1 раз в **8 часов**;
- пол не ниже 15.

За ночь 8–12 часов уходит 1–2 сытости и около 1 настроения. Со старта (70 / 78)
до «плохо» без покупок — дни, не одна ночь. Старое сохранение без `needsAt`
сначала только ставит штамп, шкалы сразу не обваливает. Пересчёт при загрузке,
каждые 20 минут и при возврате приложения на передний план.

Idle на доме зависит от шкал: сытость &lt; 40 — `idle_needs`, настроение &lt; 50 —
`idle_thoughtful`, иначе `idle_good`.

### Меню, взрослым, словарь, музыка

Меню дома: сменить локацию, новый питомец, выход из игры.
«Взрослым»: пример `8 + 5`, демо-недели вкл/выкл, сброс профиля.
Словарь — короткие определения терминов.
Музыка: два трека по кругу после входа в дом, шторка громкости, пауза на
заставке и до создания питомца. Настройки в `SharedPreferences`
(`finni_music_muted`, `finni_music_volume`).

## Логика экономики

Все расчёты в `lib/domain/economy/engine.dart`. Экраны не считают деньги сами:
вызывают `GameController`, тот зовёт `Economy` и пишет профиль.

| Действие | Условие | Эффект |
|---|---|---|
| Новый игрок | имена, тело и цвет | 100 монет, цель g1, фаза плана, шкалы 70/78, `needsAt` сейчас |
| План | фаза `planning`, сумма ≤ баланс | фаза `active` |
| Покупка | фаза `active`, хватает монет | −цена, +сытость/настроение, spentNeed/spentWant |
| В копилку | фаза `active`, хватает монет | −карман, +savings и savedThisPeriod |
| С копилки | хватает накоплений | обратно в карман, цель дальше |
| Задание | ещё не пройдено | +награда, id в `doneTaskIds` |
| Мини-игра | есть питомец | +монеты в пределах остатка 80, +6 настроения |
| Закрытие недели | есть план и фаза `active` | сверка, +80, копилка на месте, план сброшен, мини-игры обнулены |

Журнал (`ledger`) — последние 40 записей. История недель — `PeriodSummary`.

Сообщения игроку всегда нейтральные: что сделать дальше, без «ты плохой».

## 3D-питомец

В `assets/models/finni/` и `assets/models/nori/` — **по 15 GLB** (риг Mixamo,
`withSkin`). Это не один файл с 15 анимациями: каждый клип — своя модель.
Поэтому плеер держит **два** `model-viewer`: видимый и скрытый.

После упрощения моделей вес приложения снизился: клипы **176 МБ** (Финни 110,
Нори 66) вместо **473 МБ**, debug APK около **230 МБ** вместо ~530.

Стык разовой реакции и idle может чуть дёрнуться: конец одного GLB не совпадает
с началом другого. Бесшовный blend возможен только если клипы сведут в один
файл или в одну позу. Сейчас так и задумано.

На заставке прогревается WebView и частые клипы выбранного тела (три idle и
`react_joy`). В RAM не больше 5 клипов, оба `idle_good` не вытесняются.

Сырьё Meshy — `meshy/finni`, `meshy/nori`, в git не входит.

### Idle (по кругу на одном слое, камера не крутится)

Клип идёт туда-обратно (`pingpong`, `Infinity`), без CSS-кроссфейда.

| Клип | Когда |
|---|---|
| `idle_good` | сытость ≥ 40 и настроение ≥ 50 |
| `idle_thoughtful` | настроение &lt; 50 |
| `idle_needs` | сытость &lt; 40 |

### Разовые клипы

Порядок: действие **ставит клип в очередь**. Пока игрок в задании или магазине,
файл грузится на скрытом слое. Анимация начинается, когда дом снова виден.

| Событие | Клип |
|---|---|
| Задание верно / иначе | `task_right` / `task_wrong` |
| Купил / не хватило | `buy_good` / `buy_no` |
| Положил / цель закрыта | `save_add` / `save_done` |
| Мини-игра | `react_joy` |
| Тап по питомцу | `react_joy` / `react_think` / `react_support` |
| Закрыл неделю / новая стадия | `react_joy` / `stage_baby` · `stage_teen` · `stage_adult` |

Путь: `assets/models/{finni\|nori}/{clip}.glb`. В профиле — `PetLook.body` и
`PetLook.color`. Старый JSON без `body` читается как Финни, неизвестный цвет —
как персик.

Смена клипа не пересоздаёт WebView. Смена тела — `Finni.show(body, name, …)`:
слой с уже загруженным телом показывается сразу, тот же `src` не ждёт повторный
`load` (иначе Финни после Нори «не возвращался»).

Новые GLB, шрифты, JPEG фонов и правки HTML/JS плеера — полный **Run**, не
Hot Reload и не Hot Restart.

## Архитектура

Экраны не считают экономику и не пишут `SharedPreferences` сами.

```
lib/presentation (экраны, HUD, 3D-виджет)
        ↓
  GameController          ← очередь клипов, фаза UI
        ↓
     Economy              ← правила денег, шкал, недели
        ↓
   Catalog                ← магазин, цели, задания, тела
        ↓
  ProfileStore            ← JSON `finni_profile_v1` на устройстве

lib/data/pet              ← localhost HTTP + RAM-кэш GLB + JS Finni
lib/data/audio            ← два трека, громкость
```

| Слой | Папка | Зачем |
|---|---|---|
| Вход | `lib/main.dart`, `lib/app/app.dart` | `FinniApp`, сплэш-гейт, маршрутизация по профилю |
| Общее | `lib/app/` | тема, шрифты, ассеты, клипы, локации, сутки, подсказки, вёрстка |
| Домен | `lib/domain/models.dart` | профиль, питомец, план, задания, магазин |
| Домен | `lib/domain/content/catalog.dart` | статическое содержимое |
| Домен | `lib/domain/economy/engine.dart` | все правила |
| Данные | `lib/data/storage/profile_store.dart` | чтение/запись/сброс |
| Данные | `lib/data/pet/` | сервер GLB, кэш, мост `prepare` / `resume` / `applying` |
| Данные | `lib/data/audio/music_service.dart` | фон |
| Состояние | `lib/presentation/state/game_controller.dart` | единственная точка мутации профиля из UI |
| Экраны | `lib/presentation/screens/` | дом, план, магазин, задания, игры, копилка, прогресс, меню |
| Виджеты | `lib/presentation/widgets/` | оболочка, иконки, подсветка, `LivingPet` |

`GameController` — `ChangeNotifier`. После успешного `Economy.*` вызывает
`_commit`: копирует `message` / `nextStep`, пишет стор, `notifyListeners`.
Клипы: `queueEventClip` (событие с другого экрана), `presentQueuedClip`
(вернулись на дом), `playClipNow` (тап, закрытие недели).

Профиль (`GameProfile`): имя, флаги интро и подсказок, демо, питомец, локация,
монеты, копилка, цель, номер и фаза недели, план, траты, задания, журнал,
история, потолок мини-игр, `needsAt`.

Платформенный раскол 3D:

- `pet_model_runtime_io.dart` / `finni_model_view_io.dart` — Android и десктоп;
- `*_stub.dart` — web и тесты без HTTP-сервера.

## Стек

Мы выбрали стек:

| Что взяли | Зачем |
|---|---|
| Flutter / Dart `^3.13.3`, Material 3, Android minSdk **26** | Один клиент под ТЗ: Android 8+, портрет от 360 dp, планшет как плюс. Второй нативный проект не нужен. Сборка и прогон — Android Studio. |
| Слои `UI → GameController → Economy / Catalog → ProfileStore` | Пункт 3.2 ТЗ: контент и правила отдельно от экранов. Кнопки не считают деньги. |
| `shared_preferences`, ключ `finni_profile_v1` | Прогресс только на устройстве. Нет сервера, аккаунта, почты и телефона. |
| `webview_flutter` + `model_viewer_plus` | 3D без своего движка. Каждый клип — свой GLB, его можно заменить файлом. |
| Два слоя `model-viewer` в одном WebView | Финни и Нори не путаются, если тело сменить быстро. |
| `audioplayers` | Фон из `assets/audio`, без сети. Выключается с дома. |
| `flutter_animate` | Короткое появление блоков, не игровой цикл. |
| Golos UI и PT Root UI | Бесплатные шрифты ParaType, лицензия SIL OFL 1.1: можно пользоваться, встраивать в приложение и отдавать вместе с проектом. Тексты лицензий — `assets/fonts/OFL-Golos-UI.txt` и `OFL-PT-Root-UI.txt`. Иконки — Material Icons, не картинки-буквы. |

Почему не Unity / не свой бэкенд / не Kotlin-only: сдача — Android-прототип с экономикой, заданиями и 3D-питомцем, без кабинета, без облака и без магазина в первом заходе. Flutter закрывает UI, тесты правил и APK из одного репозитория. Сервер ТЗ не требует и ломал бы «без ПДн». Свой 3D-движок на хакатоне дороже, чем `model-viewer` и набор GLB.

Преимущества этого выбора и подхода к разработке:

- Один код на телефон и планшет: свои JPEG и «прибитые» кнопки, без двух вёрсток с нуля.
- Формулы и каталог правятся в `Economy` / `Catalog`, экраны только вызывают контроллер. Новое задание или товар не требуют переписывать дом.
- Автотесты бьют в правила (план, минус, неделя, шкалы, клипы), а не в WebView. `flutter test` гоняется без эмулятора.
- Цикл офлайн: сеть нужна только локальному HTTP для GLB внутри приложения. Магазин, задания и копилка работают без интернета.
- Нет аккаунта, рекламы и IAP — меньше поверхность и проще сдача по безопасности ребёнка.
- 3D меняется ассетами: после замены моделей вес клипов упал с 473 МБ до 176 МБ, на POCO M8 5G прогон прошёл ровно.
- Два слоя плеера убрали путаницу тел при быстрых тапах — это баг архитектуры ассетов, не «ещё один экран».
- Профиль в одном JSON: сброс у взрослого, сохранение после перезапуска, старые сейвы читаются без падения.
- Шрифты бесплатные (OFL), секретов и keystore в git нет.

В UI нет Roboto. **Golos UI** и **PT Root UI** — свободные шрифты ParaType
по лицензии SIL Open Font License 1.1. Ими можно пользоваться в этом
приложении и в других проектах: встраивать, распространять вместе с кодом,
менять начертания, если оставляете текст OFL. Платить за них не нужно.
Лицензии лежат в `assets/fonts/`.

| Где | Шрифт | Лицензия |
|---|---|---|
| Заголовки, имя питомца | PT Root UI | SIL OFL 1.1, бесплатный |
| Текст, кнопки, поля | Golos UI | SIL OFL 1.1, бесплатный |

## Требования и запуск

Нужны Android Studio, Android SDK, эмулятор (лучше 4+ ГБ RAM, API 26+),
Flutter (`flutter doctor` без ошибок по Android), плагин Flutter в Studio.

1. `File → Open` — корень **`finpet`**, не только `android/`.
2. В терминале Studio: `flutter pub get`.
3. Device Manager → AVD → выбрать device. Конфигурация: `lib/main.dart`.
4. **Run** (зелёный треугольник). Не Debug, если на старте висит логотип Flutter:
   Debug иногда идёт с `--start-paused`.
5. Первая сборка долгая (Gradle, NDK, WebView). Дальше быстрее.

После пересборки Studio само открывает приложение и иногда долго сидит **до**
заставки: ставится новый APK, отладочный мост ещё не отдал первый кадр. Это не
зависание игры. Force Stop и запуск с иконки — обычный холодный старт, без
отладчика, заставка сразу.

После иконки: фон загрузки (~8 с) → приветствие → персонаж, цвет и имя →
локация → дом.

| | Кнопка | Windows |
|---|---|---|
| Hot Reload (мелочи UI) | жёлтая молния | `Ctrl+\` |
| Hot Restart (экраны, фон, виджеты) | круглая стрелка | `Ctrl+Shift+\` |

Смена фона загрузки, иконки, GLB, шрифтов, HTML плеера или Gradle — полный **Run**.

Номер эмулятора (`5554` / `5556`) не зашит: смотрите `flutter devices`.

```powershell
flutter devices
flutter run -d <id>
```

Остановка: `q`. Сброс: меню «Новый питомец» или «Взрослым» → «Сбросить тестовый профиль».

### Сборка APK

Без магазина, для эмулятора и телефона:

```powershell
flutter test
flutter build apk --debug
```

Файл: `build/app/outputs/flutter-apk/app-debug.apk` (в git не входит).
`flutter build apk --release` собирается, но пока подписан debug-ключом — в RuStore не грузить. Свой `.jks` и смена `com.example.finpet` — когда пойдём в магазин. Подробности: [`docs/handover.md`](docs/handover.md).

Если сборка падает: в репозитории уже `kotlin.incremental=false` (кэш Kotlin на
разных дисках). Нет device — `flutter devices`. Белый экран — Force Stop, снова Run.

### Браузер

Чтобы посмотреть приложение в браузере, в корне проекта:

```powershell
flutter pub get
flutter run -d web-server --web-port 8080 --web-hostname 127.0.0.1
```

Потом откройте http://127.0.0.1:8080. Сервер сам не поднимается — команду
нужно запустить. 3D в браузере — заглушка, живой питомец только на Android.
